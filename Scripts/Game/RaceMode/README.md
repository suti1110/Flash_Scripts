# 레이스 경기 정보용 경로

## 씬에서 수정하는 방법

1. `FourTrack` 또는 `MirrorDive` 씬을 연다.
2. `RaceModeManager`를 선택한다. 자식 `Race Progress Route` 아래에 시작, 경유 지점, 결승 오브젝트가 있다.
3. Scene 뷰의 청록색 연결선과 번호를 확인하고 지점을 이동한다. 각 지점에 경로 길이 기준 진행률도 표시된다.
4. Inspector의 **경로 지점** 배열 순서가 시작 → 경유 지점 → 결승인지 확인한다. Hierarchy 순서만 바꿔서는 경로 순서가 바뀌지 않는다.
5. **경유 지점 추가 (결승 바로 앞)** 버튼으로 마지막 구간 중간에 지점을 추가할 수 있다. 다른 구간에 넣으려면 배열에서 순서를 옮긴다.
6. 변경한 씬을 저장한다. 지점 이동과 추가는 Undo로 되돌릴 수 있다.

지점은 빈 오브젝트이므로 실행 중 화면에 나타나지 않는다. 씬의 Gizmos를 켜면 편집용 경로가 보인다. Inspector의 **위치 보기** 버튼으로 특정 지점을 선택하고 화면을 이동할 수 있다.

## 진행률 계산

`RaceModeManager.Update()`가 서버에서 0.2초마다 선수 위치를 읽는다.
`TryEvaluateProgress()`는 모든 선분을 비교해 선수에게 가장 가까운 구간과 그 구간 안의 위치를 구한다.
`시작부터 해당 위치까지의 경로 길이 / 전체 경로 길이`가 진행률이다.
계산 결과는 `PlayerMatchState`의 NetworkVariable로 공유되고 `MatchInfoUI`가 표시한다.

앞 지점을 순서대로 통과해야 한다는 조건은 없다. 우회하거나 지름길로 뒤 구간에 도착하면 그 위치로 계산된다.
역주행하거나 리스폰하면 진행률도 현재 위치에 맞게 감소한다.
HUD의 `ROUTE` 수치는 현재 위치 뒤에 있는 경유 지점 수이며 체크포인트 통과 기록이 아니다.

`높이 차이 무시`는 **Y축을 제외하고 XZ 평면에서 계산**한다.
FourTrack은 수평 코스라 켜져 있고, MirrorDive는 높이로 구간을 구분해야 하므로 꺼져 있다.

## 실제 경기 규칙과의 관계

이 경로는 경기 정보 표시용이다. 리스폰 지점, 실제 체크포인트, `FinishLine`의 서버 완주 판정은 별도로 동작한다.
경로 끝에 가깝다는 이유만으로 우승하지 않으며, 완주 판정 전에는 서버가 진행률을 99.9% 이하로 제한한다.
실제 결승 진입이 확정되면 우승자의 진행률을 100%로 바꾼다.

## 경로를 배치할 때 확인할 점

- 굴곡마다 지점을 추가해 연결선이 실제 코스 동선을 따라가게 한다.
- 서로 다른 구간이 같은 공간에서 교차하거나 겹치면 위치만으로 어느 구간인지 구분할 수 없다. 높이가 다른 코스는 높이 무시 옵션을 끄고 경로를 실제 높이에 맞춘다.
- 지점 참조가 비어 있으면 잘못된 구간을 연결하지 않고 계산을 중단한다. Inspector에 누락된 번호가 표시된다.
- 같은 위치의 지점 두 개는 길이가 0인 구간이므로 계산에서 제외된다. Inspector에서 경고를 확인하고 이동하거나 배열에서 제거한다.

기존 숫자 좌표는 두 씬의 오브젝트 위치로 그대로 이전했다. 새로운 동선을 만들 때는 이 오브젝트들을 직접 수정하면 된다.
